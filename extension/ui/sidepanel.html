纯本地 = 所有数据只进本机 xprobe.db，一条都不出机器。云端 = 登录后，「我的」每日指标与关注台账上送 api2.mingzhang.cc，标杆账号/帖子按台账流水推到同一个地址（你自己的 boot4 Java 库，落「私有账层 + 实体层」，不动后台人工策展的那两张表）。出本机的域名只有这一条，验证码、登录、每日指标上送、推标杆四件事都走它。切回纯本地 = 只停上送，本地一个字节没动过。 「切到云端」这颗钮只是打开弹窗：里面把两种模式各传什么说一遍，登录成功那一刻才真的切过去（没有登录态的「云端模式」等于开着一扇没接通的门）。已经登录过时，「切回纯本地」只停上送、保留登录态（下次切回云端不用重新收验证码）；要抹掉身份得在弹窗里按「退出登录」，那一步有二次确认。身份只存在本扩展自己的存储里，面板不回显 token。
云端接口
现在打的是：线上（读 ❓ 看两档各是什么）
验证码、登录、每日指标上送、推标杆四件事永远只打**一个**地址，这一行选的就是那一个。线上 = https://api2.mingzhang.cc（部署好的那台 boot4）；本机 dev = http://127.0.0.1:28081（你自己正在跑的 boot4，端口抄它自己的 application-dev.yml，不是猜的）。两档地址写死在扩展代码里，这里只能二选一、填不进第三个地址——「设置里给个输入框随便填 URL」等于把「出本机只走回环与自家域名」那条红线当场作废，所以不做。 换档不改本机任何一个字节，也不动「运行模式」那颗闸：纯本地在哪儿都不发。 两档的登录态各存各的：线上换来的 JWT 不会跟着切档发到 localhost（对面是另一个进程，认不出你，还可能把你的数据写进不该写的库），dev 那档要在弹窗里重新登录一遍（本机 boot4 起好了才收得到验证码）。 推标杆的水位也按档各存一本：切到 dev 是从头重放，不继承线上推到第几行——否则「换个档」就等于把 dev 从没收到过的行当成已同步，那批行永远推不出去（宁可重推，不可漏推；对面按 用户+设备+台账行号 去重，重推不落第二行）。 本机 dev 这一档还要 boot4 放行跨域：Chrome 发出去的请求带的 Origin 是 chrome-extension://<扩展ID>（下面那行可复制），CorsConfig 的白名单里没有它 ⇒ Spring 的 CorsFilter 在任何 Controller 之前直接回 HTTP 403 纯文本「Invalid CORS request」，面板会照实说「被服务端跨域挡了」——那不是登录问题，重收验证码没用。

第七颗「回帖」＝详情页一稿草稿
右缘那列钮排的最后多一颗「回帖」（在「标帖」下面、守卫灯上面），它**只在这颗闸开着时露面**——关着时它 display:none、卡片整棵不存在，连一条请求都不发，留一颗点下去注定没反应的入口不如不放。点开是一张卡片：顶上写清这次要发的是哪一条（@作者 · 帖子 id · 正文多少字），中间是那帖的原文，下面是草稿框（可以在这儿直接改字，改完的算最新草稿），两枚钮是「写一稿」和「复制草稿」。目标只有帖子详情页那一条：首页/列表一屏好几条，选哪条都是猜，宁可不开这一腿也不猜。换页时草稿自动清空——留着旧帖那段字、目标行却指向新帖，最容易让人顺手发出去。「复制」只写剪贴板；这一腿从不点页面里任何钮、不往回复框里打字（红线 RL-1：只观测、只替你准备）。这一世问了几次、断了几次也在这张卡的最后一行念出来（SW 那份实时账，重开浏览器归零）。
