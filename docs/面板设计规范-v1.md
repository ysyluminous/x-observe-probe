## 2 状态

| 归属 | 定义 | 当前证据 | 更新时机 |
| --- | --- | --- | --- |
| **A 模块级 UI 状态**（brief 说的「React 状态」在本栈的对应物） | 只活在当前面板内存、关掉即丢；不得是真相源 | `extension/ui/sidepanel.js:20-23`（`db`/`dbBusy`/`dbAt`）、`:246`、`:303`、`:362` 注释明说「render 每次重建整棵树，存 DOM 上会被自己刷掉」 | 用户操作 / 轮询回包到达时赋值，然后由 `render()` 重放（`sidepanel.js:60`、`:973`） |
| **B 扩展 storage** | 用户偏好、按天的小计数、跨窗口共享 | `extension/ui/sidepanel.js:553/559`（`repl` 评论数）、`extension/ui/editor.js:66`（`SERIES_KEY`）、`extension/background/sw.js:329/342`（带回调的 set/get） | 写入必须带回调处理失败（`sw.js:324-329` 注释：旧写法无条件 `res({ok:true})` 是坑）；只在事件里写，不在 900ms 轮询里写 |
| **C 后端 / 本机宿主库** | 采集数据、序列、账号态，唯一真相源 | `extension/background/sw.js:120`（`sendNativeMessage`）、`extension/ui/sidepanel.js:982`（`fetchDb`）、`:21-23`（30 秒才读一次） | 面板只读；任何「本地算出来的数」不得回写覆盖后端（`handoff/art-020-hot-board.md:50` 只走现有 sink） |

**命名规则**：A 用 `camelCase` 且带用途后缀（`rankSortBy` / `tlLimit` / `dbBusy` / `impEdit`，见 `sidepanel.js:303`、`:362`）；B 的 key 用小写短名并集中声明常量（现状 `editor.js:66` 有 `SERIES_KEY`，但 `sidepanel.js:553/559` 把 `'repl'` 写了两次字符串字面量 → 违规，见 §4 R6）；C 的字段名以 `st.*` 回包为准，不另起别名。

**硬规则**

- **S1 单一真相源**：同一事实只允许存在于 A/B/C 中的一层。当前 `st.rndMax` 既在 `st` 又在输入框（`sidepanel.js:509-515`），靠 `rndDirty` / `activeElement` 守卫避免互相覆盖——这是允许的**投影**，不是两份真相；新增字段必须先写明它属于哪层。
- **S2 状态落点不被重画抹掉**：动作结果写 `#setNote`（`sidepanel.html:220`）/ `#modeStat` / `#envStat`，不许 prepend 进 `#report`（`skills/docs/UIX.md:35` D-4；`sidepanel.js:625`、`:1096-1097` 已有血的教训）。
- **S3 轮询不写 storage、不新建宿主进程**：`sidepanel.js:2013` 的 900ms 只做 `refreshState()`；`sendNativeMessage` 每次新起宿主进程（`sidepanel.js:21`、`sw.js:446`），故本机库只允许进广场时读 + 30 秒刷（`sidepanel.js:2018`）。
- **S4 重画腿不得重建输入 / 弹窗**：照 `syncModeModal()` 做「建一次、之后只更新」（`skills/docs/UIX.md:42` D-11）；`sidepanel.js:496` 每次 render 重挂 `tlUserModalNode()` 是 UIX-22 未修项（`skills/docs/UIX.md:111`），新增弹窗一律不许照抄这个写法。
- **S5 空值**：`st` 可以为 null（`sidepanel.js:501-507` 注释），任何状态读取先判空，不许在 promise 里抛 `Cannot read properties of null`。
- **React 映射（若将来引入）**：A 层整体搬进组件 state / context，B/C 层保持现状不变；view.js（L2）直接当纯 selector 用，**不许**因此重写采集口径。这条只是预留，本卡不引入 React。

## 3 样式

- **token 唯一来源**：`extension/ui/sidepanel.css:5-10` 的 `:root`（`--bg` / `--surf` / `--line` / `--ink` / `--dim` / `--acc` / `--amber` / `--red` / `--blue` / `--sans` / `--mono`）。新增颜色先加 token，再在类里 `var(--x)`。
- **语义 class 而非颜色值**：`view.js:11-13` 的 `row/line/fold` 的 `sty` 字段只允许传 `ok` / `warn` / `bad` / `pre`（`view.js:38`、`:104-112`），由 `sidepanel.js:452-469` 落成 class，颜色在 `sidepanel.css:164-169` 定义。**禁止把 `#RRGGBB` 或 `rgb()` 塞进 `sty`**。本轮 `extension/ui/*.js` 硬编码色零命中，纪律现状良好，要保持。
- **唯一允许的内联样式**：动态几何量（进度条宽度 `sidepanel.js:86` `fill.style.width = pct + '%'`）。除此之外一律 className；需要新样式就加 CSS 类。
- **禁止的写法（举当前真实反例）**：
  - 同一语义多份色值：绿有 `--acc:#5FD3A0`（`sidepanel.css:8`）、`.ok{color:#4ec98a}`（`:167`）、`.cool.ok{color:#A9DEC3}`（`:213`）三份；红有 `--red:#E8786C`（`:8`）、`.bad{color:#e06c60}`（`:169`）、`.cool.bad{color:#F0B7B0}`（`:212`）三份 → 收敛时统一 `var()`，不新增第四份。
  - 裸写边框/背景硬编码：`sidepanel.css:89`、`:212-213`、`:219`、`:222`；新代码禁止，存量按 §7 第 3 批逐条替换。
  - `!important`、在 JS 里拼 `style="..."`、在 `view.js` 里返回带颜色的字段——均为违规（三者本轮实测零命中）。
  - 弹窗皮肤只许复用 `.modal*` / `.tlModal*`（`skills/docs/UIX.md:41` D-10），抄第二份样式列表 = 违规。

## 5 体积

- **上限**：单文件 400 行、单函数 50 行（brief 建议值，`brief-44-面板设计规范.md:25`）。现状全线超标（§0.2：`core.js` 7559 行 / 34 个超长函数），**这是存量债务，不是本卡要一次性清掉的账**。
